## What we're building

A pipeline that turns KTU B.Tech CSE syllabus topics into ~60-second animated lesson reels (Malayalam–English, AI voiceover), and a web app where students watch them by semester, subject and module.

Pipeline: `curriculum/ktu-2024-cse.csv` → `lessons/<topic-id>.json` (drafted, then reviewed) → `scripts/generate-voice.ts` (Sarvam TTS) → Remotion composition → `web/public/videos/<topic-id>.mp4` → `web/public/lessons.json` → web app.

## Stack

- Node 18+, TypeScript everywhere, npm
- Video: Remotion (React), in `video/`
- Voice: Sarvam AI text-to-speech, model `bulbul:v3`, language `ml-IN`
- Validation: zod schemas in `shared/`, used by every script and the composition
- Web app: Vite + React, in `web/`
- Fonts via `@remotion/google-fonts`: Manrope (headlines), Noto Sans Malayalam (Malayalam text), IBM Plex Mono (labels and code)

## Curriculum CSV

Columns: `ID, Sem, Subject, Module, Reel topic, Priority, Status, Module theme, Course code`.
- `ID` is `<SUBJ>-<module>-<nn>` (e.g. `PIC-4-01`). It never changes once a lesson exists.
- `Status` in the CSV is the Sheet's status at export time; `status.ts` reports the repo's view. Don't write back to the CSV; the human updates the Sheet.
- Subject codes: ATP, FOC, PIC, DM, TOC, DSA, OOP, DBMS, OS, COA, CN, DAA, ML, MC, CD, ACS, CS.

## Lesson schema (summary)

Defined in `shared/lesson-schema.ts`:

```
topicId        "PIC-4-01" (must exist in topics.json)
title          reel title shown in the app
language       "ml-IN"
example        one sentence: the real-life example this reel uses (required)
review         { status: "pending" | "approved" | "changes", reviewer?: string, notes?: string }
quiz           3 items of { question, options[4], answer (index) }  (optional until Phase 5)
scenes         4–7 scenes
```

Every scene has `id`, `type`, `label`, `narration`, `caption`, plus:
- `hook`: `headline`
- `concept`: `headline`, optional `body`
- `example`: `setup`, `payoff` (required: at least one per lesson)
- `flow`: `headline`, `steps` (2–4 of `{ title, sub }`)
- `compare`: `left`, `right` (each `{ title, points[] }`)
- `code`: `language` (c | python | java | sql | text), `lines[]` (≤ 12), `highlight[]` (line numbers in narration order)
- `steps`: `headline`, `items[]` (≤ 6)
- `table`: `columns[]` (≤ 4), `rows[][]` (≤ 5)
- `takeaway`: `headline`

Any scene may also carry a `visual`: the existing cue-timed icons-and-arrows format already in the schema. Keep that format as it is when adding the new fields; `concept` and `example` scenes should always have one.

Semester, subject and module come from topics.json via `topicId`; never duplicate them in the lesson.

## Voice rules

- POST `https://api.sarvam.ai/text-to-speech`, header `api-subscription-key`, body with `text`, `target_language_code: "ml-IN"`, `model: "bulbul:v3"`, `speaker`. Decode base64 `audios[0]` to WAV. Verify field names against docs.sarvam.ai before changing the client.
- **Refuse to voice a lesson whose `review.status` is not `"approved"`.** A `--draft` flag may voice for preview into a separate folder that is never rendered for publishing.
- Apply `curriculum/pronunciation/<subject>.json` replacements to narration before sending.
- One request per scene, under 2,500 characters. No SSML: pauses come from punctuation.
- Malayalam in Malayalam script, English terms in English. Never romanized Malayalam.
- Write `manifest.json` with each scene's duration (via `music-metadata`) and a hash of its text; skip unchanged scenes.

## Video rules

- 1080×1920, 30 fps, composition `LessonVideo`, input prop `topicId`.
- `calculateMetadata` loads the lesson, topics.json and the manifest; each scene lasts its audio + 12 frames.
- All animation from `useCurrentFrame()`, `spring()`, `interpolate()`. No CSS transitions, timers or unseeded randomness.
- `code` scene: lines reveal top to bottom across the first 40% of the scene; highlights move through `highlight[]` evenly across the rest. Never shrink code below 34px; if it doesn't fit, the lesson needs fewer lines.
- `steps`, `table`, `flow`: items appear one at a time across the first half of the scene.
- Every reel shows the subject badge and "S<sem> · Module <m>" in the header, and ends with an end card naming the next topic in the module.
- Safe area: 80px side padding; bottom 280px only for the caption. Minimum sizes: headline 88px, body 44px, caption 40px.

## Visual style

"Backwater dusk": ink background `#0B1622`, drifting blurred teal `#2DD4BF` and turmeric `#F5B82E` shapes, off-white text `#F4EFE6`, muted labels `#8FA3B5`. Mono uppercase labels with letter spacing. Rounded boxes (20px), 2px borders, highlight in turmeric. Code syntax colours defined in `theme.ts`. Components never hardcode colours or sizes.

## Conventions

- Small typed components; no `any`; types from `z.infer`.
- Timing constants in `theme.ts`.
- Generated files (`video/public/audio/`, `web/public/videos/`, `curriculum/topics.json`) are gitignored except where noted.
- Ask before adding dependencies not listed here.

## Working rules

- Follow the phase order in PLAN.md. Finish and check one phase before starting the next.
- Check every new component in Remotion Studio before building the next one.
- When drafting lessons, use the lesson-video skill and work one module at a time.
- Never mark a lesson approved yourself. Only a human reviewer does that.
- After changing timing logic, render a short frame range to confirm it matches Studio.
